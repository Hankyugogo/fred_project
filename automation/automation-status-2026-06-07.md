## 덮어쓰기 정책

이미 만들어진 파일은 일부 덮어쓴다.

- `report.html`: 매번 최신 리포트로 덮어쓴다. 공개 URL `/report.html`도 항상 최신본을 가리킨다.
- `reports/YYYY-MM-DD.html`: 같은 날짜를 다시 만들면 그 날짜 HTML은 덮어쓴다. 다른 날짜 파일은 유지된다.
- `posts/YYYY-MM-DD.md`: 같은 날짜를 다시 만들면 그 날짜 Markdown 초안/본문은 덮어쓴다.
- `data/briefings.json`: 같은 날짜 레코드는 새 레코드로 교체된다.
- `data/market-snapshot.json`, `data/news-digest.json`, `data/market-supplements.json`, `data/watchlist-prices.json`, `data/stock-watchlist.json` 등 데이터 JSON은 실행할 때마다 최신 상태로 덮어쓴다.

## 다시 보고 싶을 때

- 날짜별 정적 HTML은 `reports/YYYY-MM-DD.html`에서 본다.
- 날짜별 Markdown 본문은 `posts/YYYY-MM-DD.md`에서 본다.
- 같은 날짜를 다시 생성해 파일이 덮인 뒤 이전 버전을 보고 싶으면 Git 커밋 기록에서 꺼내야 한다.
  - 예: `git log -- reports/2026-06-07.html`
  - 예: `git show <commit>:reports/2026-06-07.html`
- GitHub 웹에서도 해당 파일의 History에서 예전 커밋을 열 수 있다.

주의: GitHub Pages의 `/report.html`은 최신 배포본 하나만 보여준다. 특정 날짜를 고정해서 다시 보려면 `/reports/YYYY-MM-DD.html`을 사용한다.
